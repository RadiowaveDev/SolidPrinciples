# 🧱 Principios SOLID en C# - Ejemplos Prácticos

Este repositorio contiene implementaciones prácticas de los principios **SOLID** en el lenguaje **C#**. Cada principio está abordado con un ejemplo claro y autocontenible, siguiendo buenas prácticas de diseño orientado a objetos.

## 🧠 ¿Qué es SOLID?

**SOLID** es un acrónimo que representa cinco principios fundamentales del diseño de software orientado a objetos. Estos principios ayudan a escribir código más limpio, mantenible, escalable y fácil de probar.

| Principio | Nombre | Descripción |
|----------|--------|-------------|
| **S** | Single Responsibility Principle | Una clase debe tener una única razón para cambiar. |
| **O** | Open/Closed Principle | El código debe estar abierto para extensión pero cerrado para modificación. |
| **L** | Liskov Substitution Principle | Las clases derivadas deben poder sustituir a sus clases base sin alterar el comportamiento esperado. |
| **I** | Interface Segregation Principle | Las interfaces deben ser específicas y no forzar a implementar métodos innecesarios. |
| **D** | Dependency Inversion Principle | Depende de abstracciones, no de concreciones. |
